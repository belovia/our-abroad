# SSOT governance

`last_updated`: 2026-10-31

## Что является нормой

Каноническое описание **текущей реализации** — указатель `SSOT.md` и одна тема-владелец в `docs/ssot/`. Утверждённые спеки в `.agents/specs/` описывают целевой срез и эту норму не заменяют. Комментарии в коде и OpenSpec её не заменяют.

Одно определение живёт в одном файле. Второй файл даёт ссылку.

## Когда обновлять

Меняется статус, текст ошибки, таблица, роль пакета, маршрут или правило сценария:

1. Правится тема-владелец из указателя `SSOT.md`.
2. В теме и, если меняется состав тем, в `SSOT.md` ставится `last_updated`.
3. В Update Log темы добавляется строка. В `SSOT.md` строка нужна, когда меняется состав указателя.

Новая тема копируется из `docs/ssot/_templates/TOPIC_TEMPLATE.md` и добавляется в указатель.

## Противоречие и пробел

Если просьба противоречит теме, сначала показывается правка темы. Код меняется после подтверждения правки.

Пробел — поведение, которое код не определяет. Его пишут в `docs/ssot/gaps.md` и не закрывают догадкой. Формат записи:

| Поле | Смысл |
|---|---|
| id | `GAP-NNN` |
| тема | ссылка на тему-владельца соседнего факта |
| что видно в коде | наблюдение без вывода, как «должно быть» |
| чего нет | какой сценарий или ответ API не задан |
| статус | `open` |

Секреты в темы не копируются.
